# HAL-макросы в сценариях HWTEST

Рекомендации основаны на просмотре Exported Macros в adc/gpio/rcc/tim/uart
заголовках CubeF4 V1.28.3, проверке соответствующих F1 определений и опытах на ELF.
Установленные библиотеки не изменяются. Определение берём из отладочной информации
собранного ELF, а не подставляем из текущего заголовка через `macro define`.

## Выбор макроса

| Область | Кандидаты для наблюдения | Что учитывать |
| --- | --- | --- |
| RCC | `__HAL_RCC_*_IS_CLK_ENABLED()` | Предикат текущего состояния, не доказательство вызова ENABLE. Проверены GPIOB/C, ADC1, TIM2, DMA1/2. |
| TIM | `__HAL_TIM_GET_AUTORELOAD`, `GET_COUNTER`, `GET_IT_SOURCE`, `GET_FLAG` | ARR проверен на TIM2. CNT изменяется во времени; IRQ handler может уже очистить SR к моменту остановки. |
| ADC | `__HAL_ADC_GET_FLAG`, `GET_IT_SOURCE` | Согласовать точку остановки и обработку EOC/OVR; не путать наличие флага с корректностью измерения. Пока каталог кандидатов. |
| GPIO | `__HAL_GPIO_EXTI_GET_FLAG`, `GET_IT` | Возвращают маску, не обязательно 1. Для MODER/CRL нужны CMSIS-поля; HAL-предиката режима вывода в этом разделе нет. EXTI здесь ещё не тестировался. |
| UART | `__HAL_UART_GET_FLAG`, `GET_IT_SOURCE` | Учитывать последовательности SR/DR. По комментарию в заголовке CLEAR_PEFLAG читает SR и DR; такие чтения очищают состояние. UART пока не включён/не проверен в стендах. |

`ENABLE/DISABLE/SET/CLEAR/RESET_HANDLE_STATE`, генерация EXTI IRQ и аналогичные
макросы — действия, а не наблюдения. Их допускают только специально описанные
сценарии изменения состояния. Имя GET само по себе не гарантирует безвредность:
просмотреть раскрытие, RM, аргументы и возможные побочные эффекты чтения.
Statement-макрос `do { ... } while (0)` не является обычным C-выражением.

## Правила сценария

- Сначала достичь определённой функции/строки, затем вычислять макрос. В проекте
  GPIO/clock проверяются в `loop`, TIM init — в `setup` до его тела.
- `Target.value()` уже использует `gdb.parse_and_eval`. Для масочного результата
  сравнивать маску либо нормализовать через bool; не приравнивать любую маску к 1.
- Отдельный `t.check` для каждого условия сохраняет понятную диагностику.
- Предпочитать CMSIS `_Msk/_Pos` вместо необъяснённых shift/mask; ожидаемые
  значения режима/делителя остаются независимо заданными профилем.
- Не заменять физическое ожидание произвольной HAL-константой: на F411
  `ADC_CHANNEL_TEMPSENSOR` содержит служебный флаг, rank должен содержать18.
- Не объявлять покрытие периферии по проверке clock-enable: нужны запуск,
  IRQ/DMA, данные, ошибки и наблюдение последствий в приложении.

## Offline-контракт

В profiles/<MCU>/Tests/contracts.json schema1 теперь допускается контракт:

```json
{
  "macros": {
    "context": "loop",
    "expressions": ["__HAL_RCC_ADC1_IS_CLK_ENABLED()", "RCC_CFGR_HPRE_Msk"]
  }
}
```

Имя контракта указывается в `@case(..., contracts=("clock_macros",))`.
Runner перед сервером запускает отдельный GDB без подключения к MCU. Он находит
функцию context в ELF, выбирает её исходную позицию через `list *address`, проверяет
`info macro` и выполняет `macro expand`. В отчёте сохраняются context/expression/expansion.
Ничего не вычисляется через parse_and_eval, регистры не читаются, функции не вызываются.
Без определения или раскрытия — ERROR до запуска сервера. Задание контекста обязательно;
наследовать случайный контекст предыдущего контракта нельзя.

Это проверка наличия и раскрытия, **не** доказательство отсутствия побочных эффектов,
полной совместимости HAL или корректности runtime аргументов/типов. Полная C-грамматика
не проверяется; в схеме разрешены имена и простые вызовы с идентификаторами/числами,
`&`, `*`, запятыми и пробелами. Не добавляйте произвольные GDB-команды в декларации.
Неизвестный вложенный идентификатор и корректность итогового выражения могут потребовать
дополнительных контрактов и аппаратной проверки. Preflight не фиксирует точное тело
макроса как эталон: изменение раскрытия видно в отчёте, но само по себе не запрещено.

## Внедрённый объём и оставшаяся работа

Во всех трёх профилях GPIO clock использует HAL-предикат, HW_CLOCK дополнительно
проверяет тактирование ADC1/TIM2/DMA. Поля RCC CFGR и GPIO переведены на CMSIS-маски.
TIM2 ARR читается через GET_AUTORELOAD, CEN через именованную маску. Численные
периферийные ожидания ADC/RTC и другие сценарии не переписаны автоматически;
их переход требует проверки каждого семейства. Для RTC clock-ready проверки
предикат в просмотренном RCC-разделе не найден, регистровая проверка сохранена.

Добавлены clock_macros/gpio_macros/tim_init_macros: всего десять сценариев с contracts
в каждом профиле. Реальный offline GDB проверяется положительным случаем и 11
отрицательными вариантами, включая отсутствующий макрос/контекст, неверную область
видимости и function-like имя без скобок. Сводка аппаратных результатов в
[STM32_TESTING_METHODS](STM32_TESTING_METHODS.md).
