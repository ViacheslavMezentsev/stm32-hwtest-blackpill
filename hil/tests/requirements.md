# Требования к CMSIS-приложению

Каждый сценарий начинается со сброса. Плату выбирает сборка (пресеты HIL_F411CE и HIL_F401CC)
через конфигурацию прогона hil/sessions/<mcu>.toml: описание MCU (hil/profiles), параметры
сценариев (hil/api.toml) и файл данных платы (hil/boards). Ожидания, которые зависят от платы
(канал датчика температуры, адреса заводских калибровок, объём RAM, вывод светодиода), сценарии
берут из файла данных платы. Остановки GDB влияют на время; проверки не измеряют энергопотребление,
не являются метрологией и не доказывают покрытие кода.

## HW_BOOT
Приложение достигает loop() без platform_fault; SystemCoreClock равен 16 МГц, источник SYSCLK — HSI,
делители AHB/APB1/APB2 равны 1 (поля RCC_CFGR по адресу регистра).

## HW_CLOCK_GPIO_CONFIG
В platform_led_toggle(): HSI включён и готов, SYSCLK от HSI без деления шин, SystemCoreClock 16 МГц,
SysTick 1 мс (LOAD = 15 999) от ядра с прерыванием; PC13 — двухтактный выход низкой скорости без
подтяжки, тактирование GPIOC включено. Макросы CMSIS — контракт cmsis_clock_gpio.

## HW_GPIO
Светодиод PC13 (активный низкий уровень) на трёх последовательных входах в platform_led_toggle()
находится в состояниях выключен, включён, выключен. Проверяется регистр ODR, не свечение.

## HW_BOARD_PROFILE
Описание MCU, файл данных платы и сборка относятся к одной плате: имя платы входит в название MCU,
сборка определяет макрос устройства из файла данных (STM32F411xE или STM32F401xC). Файл данных и
api.toml захвачены прогоном. DEV_ID по адресу из описания совпадает с ним, размер Flash по регистру
не меньше описания. Таблица векторов: начальный указатель стека в SRAM (не выше конца RAM из файла
данных, стек растёт вниз) и выровнен на 8 байт, вектор сброса в Flash описания, код Thumb. Чтение
регистра периферии как памяти отклоняется (outside_window). Профиль сохраняется в записях результата.

## HW_ADC_INIT
ADC1 сканирует два канала: датчик температуры (18 у F411, 16 у F401 — из файла данных), затем VREFINT
(17); режим сканирования, ADON, запросы DMA непрерывно (DDS), внутренние каналы включены (TSVREFE).
DMA2 stream 0 передаёт полуслова с инкрементом памяти из ADC1->DR. Контракт cmsis_adc_dma.

## HW_ADC_RUNTIME
Одна завершённая DMA-последовательность публикуется приложением: adc_sequences = 1, качество
ADC_FACTORY, оба отсчёта в пределах 1…4094, VDDA в окне приложения 2400–3600 мВ (hil/api.toml). Это
проверка правдоподобия, не метрология.

## HW_ADC_DMA_PUBLICATION
Естественное прерывание DMA2 stream 0 (исключение DMA2_Stream0_IRQn + 16 = 72) приходит с TCIF0 без
флагов ошибок, NDTR = 0, поток остановлен. До app_adc_complete() измерение не опубликовано; после
него оба отсчёта из буфера DMA публикуются ровно один раз с качеством ADC_FACTORY.

## HW_ADC_WRITER
Счётчик app_state.adc_sequences изменяет loop(), вызванная из main(); остановка — точка наблюдения за
записью. К моменту счёта измерение уже сохранено (качество ADC_FACTORY), счётчик равен 1.

## HW_ADC_SERIES
Серия из пяти измерений (hil/api.toml) снимается на входах в platform_led_toggle() и сохраняется в
записях результата: номера последовательностей идут подряд с 1, качество везде ADC_FACTORY, среднее
VDDA в окне приложения, разброс VDDA не больше 50 мВ, температуры — не больше 3 °C. Это проверка
устойчивости при неизменных условиях, не оценка точности.

## HW_ADC_DISABLED
Сброс ADON перед запуском преобразования приводит к platform_error() с кодом platform_fault = 2.

## HW_ADC_TIMEOUT
При запрещённом прерывании DMA2 stream 0 приложение достигает platform_error() не ранее чем через 100
тиков (hil/api.toml), не публикуя измерение.

## HW_ADC_BUSY
Включённый поток DMA (с корректным адресом назначения, без запуска преобразования) отвергается кодом
platform_fault = 1 до нового преобразования.

## HW_ADC_INVALID
Подставленные на входе platform_adc_convert() значения reference = 0, reference = 4095 и
temperature = 0 отвергаются: качество ADC_INVALID, VDDA и температура равны 0. Следующее обычное
измерение снова имеет качество ADC_FACTORY.

## HW_ADC_VECTORS
Подстановка заводских калибровочных отсчётов (VREFINT_CAL и TS_CAL1 или TS_CAL2, адреса из файла
данных) даёт качество ADC_FACTORY, VDDA 3300 мВ и температуру 30 000 и 110 000 м°C соответственно.
Проверяется арифметика преобразования, а не фактическая температура кристалла.

## HW_ADC_CALLBACK_SUPPRESSED
Если после завершённой передачи DMA обратный вызов app_adc_complete() возвращается сразу, приложение
достигает срока ожидания (100 тиков) и platform_error() без публикации; adc_ready остаётся false,
platform_fault = 6 (APP_FAULT_ADC_TIMEOUT). Это модель потерянного уведомления, а не отказа ADC или DMA.

## HW_TIMER
TIM2 настроен на 1 кГц (PSC = 15 999) с переполнением каждые 100 мс (ARR = 99), прерывание обновления
и счётчик включены; событие доходит до приложения. Номинальный период при HSI 16 МГц, точность
генератора не проверяется.

## HW_TIMER_IRQ_PUBLICATION
Естественное прерывание TIM2 (исключение TIM2_IRQn + 16 = 44) приходит с UIF; два завершённых
обработчика подряд публикуют по одному событию; в loop() активного исключения нет.

## HW_RTC
RTC использует делители 127/249 (1 Гц от LSI); первый alarm назначен на вторую секунду (маска даты
установлена), обработанное событие приводит к следующему alarm с другой секундой. Точность LSI не
проверяется.

## HW_RTC_DEADLINE
Если условие ожидания готовности LSI (wait_set с кодом 12) сделать невыполнимым, приложение
завершается platform_error() с кодом 12 вместо бесконечного ожидания.

## HW_SLEEP_SYSTICK
Сон обычный (без SLEEPONEXIT и SLEEPDEEP). С замаскированными прерываниями периферии SysTick выводит
ядро из WFI; прерванный контекст — команда WFI в platform_sleep(). После восстановления масок
интервал idle завершается (не меньше 499 тиков) и приложение продолжает измерения.

## HW_SLEEP_TIM2
При остановленном SysTick и единственном разрешённом прерывании TIM2 таймер выводит ядро из WFI
platform_sleep() без продвижения platform_tick; после восстановления SysTick и масок приложение
обрабатывает событие таймера и продолжает измерения.

## HW_ADC_TIMEOUT_DIAGNOSTIC

RU: При отсутствии уведомления DMA приложение ожидает не менее 100 тиков, не публикует измерение и устанавливает platform_fault=6 перед platform_error.

EN: When DMA notification is absent, the application waits at least 100 ticks, publishes no measurement and sets platform_fault=6 before platform_error.
