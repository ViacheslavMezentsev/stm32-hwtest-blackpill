# Артефакты сборки и проверки

Исходники stm32-gdbtest принадлежат отдельному репозиторию; его закреплённая копия
в `modules` используется только для чтения. Сборки, отчёты и временные файлы этого
стендового проекта находятся внутри его workspace и не включаются в Git.

| Каталог | Назначение / хранение |
| --- | --- |
| build/Debug_*, Release_*, HIL_* | Текущие раздельные CMSIS-сборки; HIL содержит manifest/session/runs. |
| build/native-adc, build/ci-reports/cmsis | Native ADC и текущие CI-результаты. |
| build/f103c8-debug-hwtest, f401cc-debug-hwtest, f411ce-debug-hwtest | Исторические HAL-сборки и аппаратные доказательства. Старые sessions после переноса не запускать как текущую регрессию. |
| examples/minimal-consumer/build | Сборка интеграционного примера, не сборка подмодуля. |
| build/*validation, *observation, *live, *experiment и аналогичные | Доказательства опытов, включая отрицательные и USB-сбои. Не удалять вместе с cache без оценки содержимого. |
| build/module-host/<id> | Воспроизводимые копии для host-тестов ядра; host.log сохраняется отдельно перед удалением копий. |
| build/relocation validation/<id> | Исходники/сборки/журналы опыта переноса и read-only ACL. В текущей очистке сохранены целиком. |
| build/module-ready/stm32-gdbtest | Первоначальный checkout новой истории; опубликован, но это Git-репозиторий, не обычный cache. Пока сохранён. |
| .work/stm32-gdbtest | Отдельный рабочий checkout для изменений ядра/документации. Исключён из Git родителя, не удалять очисткой build. |
| build/cleanup-evidence | Локальная опись очистки и сохранённые host-журналы; может содержать личные пути. |

Историческая очистка до CMSIS-переноса удаляла старые компиляторные каталоги `debug`, `debug-gcc14`,
`debug-gcc15`, `release`, `f103-debug`, предварительный export `module-export`
и копии host-проверок. Если внутри старой сборки есть hwtest/Testing, их сначала
сохраняют в cleanup-evidence. Старые `debug-hwtest` и `f103-debug-hwtest` в той
очистке были оставлены как исторические аппаратные данные; их CTest не запускать.

В рамках ревизии документации очистка не выполняется.

Перед рекурсивным удалением разрешить полный путь, проверить нахождение строго
в build текущего проекта, отсутствие reparse points и вложенных Git-репозиториев.
Не очищать работающий build/run и не удалять lock ради обхода занятого отладчика.
Доказательства отказов не заменять только успешным повтором. Обычная повторная
сборка выполняется configure/build соответствующего preset; старый cache другого
MCU или компилятора не переиспользуется.

Предлагаемый следующий шаг — воспроизводимый сбор компактного пакета доказательств:
коммиты модуля/проекта, ELF/manifest, результаты и существенные logs, с проверкой
личных данных перед публикацией. Автоматическая очистка по возрасту пока не введена.
