# Проверка владения отладчиком между проектами

Механизм и ограничения: [stm32-gdbtest](https://github.com/ViacheslavMezentsev/stm32-gdbtest/blob/b76d909f903df513156019a32479c5e3c2b2e0c3/docs/DEBUGGER_OWNERSHIP.md).
Здесь сохранён протокол опыта на стенде. Числа ниже относятся к этапу введения mutex;
последующая интеграция подмодуля проверена с 44 host-тестами. observe_sleep участвует
в том же протоколе через импорт из закреплённого модуля.

## Проверки

`python -B tools/test_module_host.py`: **41 unittest PASS**.
Новые проверки используют синтетические serial и не запускают GDB-сервер:

- процесс-владелец импортирует копию модуля из другого каталога;
- другой проект получает отказ и для openocd, и для stlink, в том числе с другим
  регистром serial; runner сохраняет ERROR и не вызывает execute;
- другой serial и другая семья отладчика могут быть заняты независимо;
- вложенный захват отклонён, исключение освобождает ресурс;
- принудительное завершение синтетического владельца позволяет новый захват;
- отдельно сохранённый handle удерживает объект после смерти владельца:
  WAIT_ABANDONED даёт ожидаемый отказ, затем ресурс доступен после проверки.

Аппаратная регрессия 2026-09-24:

- F411CE/ST-Link/OpenOCD: перенесённый read-only consumer, CTest3/3,
  verify-only, Python timeout/recovery, следующий тест PASS. Основная прошивка
  восстановлена, HW_BOOT/HW_BLINK PASS. ACL возвращён.
- F411 live Sleep через обновлённый observe_sleep: PASS, S_SLEEP30/30,
  tick+1326ms, ядро не останавливалось.
- F103C8/J-Link: HW_BOOT/HW_BLINK PASS, reset_run; известное предупреждение
  Flash128K против профиля64K сохранено. Тип MCU/профиль не менялись.

Два независимых стенда использовались параллельно на финальных smoke checks.
Конкуренция **одного** serial проверена host-процессами до аппаратного доступа;
одновременное управление одним реальным MCU намеренно не выполнялось.
Локальные отчёты: build/relocation validation/578902a70813434aa515ceaa38029d1a,
build/shared-lock-sleep и обычные runs f103c8-debug-hwtest. Это выборочная
аппаратная регрессия механизма, не повтор полного набора периферийных тестов.
