# F401CC по маркировке на экземпляре с DEV_ID 0x431

## Условия

2026-09-24 владелец явно запросил запуск неизменённой сборки f401cc,
ориентируясь на маркировку STM32F401CCU6. ST-Link/SWD, OpenOCD 0.12.0;
BluePill/J-Link не использовалась. История идентификации:
[PROFILE_MIGRATION](PROFILE_MIGRATION.md).

ELF SHA-256: `415411b1213ac6240e132a8ecc4a881394e906e1f214733217b7e6a2097707bc`.
Flash образа 12224 байта, STM32F401xC, начальный SP 0x20010000.
Исходники, IOC, ELF, обычный target.toml и ожидания сценариев не изменялись.

Отдельный скрипт `Tests/experiments/f401_marking.py` передаёт существующему
исполнителю runtime-копию профиля с ожидаемым DEV_ID 0x431 вместо 0x423.
Исходный профиль, причина эксперимента и override включены в JSON/JUnit.
Manifest по-прежнему проверяется относительно исходного профиля и ELF;
его совпадение не является доказательством совместимости с этим экземпляром.
Остальные механизмы Flash verify, fault breakpoints, таймаут/recovery сохранены.
Это ограниченный эксперимент, не общий флаг отключения identity.

## Результаты неизменённой прошивки

| Сценарий | Результат | Наблюдение |
| --- | --- | --- |
| HW_BOOT | ERROR: timeout 20 s | main достигнут, loop не достигнут |
| HW_CLOCK | ERROR: timeout 20 s | также требует достижения loop |
| HW_ADC_DMA_INIT | PASS | поля HAL и регистры, включая rank1=16/rank2=17 |
| HW_TIM2_INIT | PASS | PSC=7999, ARR=99, до запуска |
| HW_RTC_INIT | PASS | LSI, делители и настройки RTC |

Первый запуск записал образ; GDB прошёл проверку содержимого Flash и достиг main.
На таймауте агент не сохранил итоговый agent-result, поэтому частичные наблюдения
доступны в gdb.log, а не в пустом checks итогового ERROR. Последующие init-сценарии
подтвердили Flash через штатный механизм. После каждого запуска выполнен reset/run.

Диагностическое подключение с halt/backtrace показало:

```text
Error_Handler -> setup (User/Src/program.cpp:21) -> main (Core/Src/main.c:108)
htim2.State = HAL_TIM_STATE_BUSY
uwTick = 1; app_state.adc_sequences = 0; CFSR = 0
```

В main два последовательных `setup()` и два `loop()`. Второй setup вызывает
HAL_TIM_Base_Start_IT для уже запущенного TIM2; приложение переходит в Error_Handler,
где отключает IRQ и остаётся в бесконечном цикле. Это объясняет отсутствие мигания
и оба таймаута. Reset/run снимает отладочную остановку, но приложение повторяет
сбой: нельзя описывать конечное состояние как нормально работающую прошивку.

Локальные отчёты: `build/f401-marking-experiment/`; стек —
`build/f401-marking-diagnostic/gdb.log`. Серийный номер в Git не включён.

## Вывод и продолжение

Сборка F401CC исполняется до настройки периферии на данном экземпляре.
PASS регистровой конфигурации ADC не доказывает, что канал16 физически измеряет
температуру: конверсии, DMA runtime, IRQ, мигание и Sleep пока не проверены.
Результаты не подтверждают подлинность или совместимость обычного STM32F401CC.

Следующий шаг — удалить дубли setup/loop в USER CODE, создать новый ELF/manifest
и повторить эксперимент с тем же явно отмеченным override. Результаты новой
сборки хранить отдельно от проверки «как есть». Затем проверить ADC runtime и
осмысленность температуры/VREFINT, не подгоняя ожидания под полученные значения.

Повторение выбранных проверок на подтверждённом стенде:

```powershell
python -B Tests/experiments/f401_marking.py --stand Tests/stands/blackpill.local.toml --test HW_ADC_DMA_INIT --test HW_TIM2_INIT --test HW_RTC_INIT
```

`--test ALL` останавливает набор на первом ERROR; FAIL сохраняется и позволяет
продолжить. Стандартные presets по-прежнему отвергают DEV_ID 0x431 для f401cc.
